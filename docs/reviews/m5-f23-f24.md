## F23: `ENV BENCHLENS_ALLOWED_HOSTS=localhost` in the image

`check_host` serves `localhost` and any IP literal unconditionally once the check is on, and `checks_host()`
is `no token || loopback || allowed_hosts non-empty`. Setting the list to `localhost` turns the check on
for a token-protected container without serving anything new; `hosts_served()` hides the redundant
`localhost`. Correct.

Every way of running the image (checked with an image built from the branch, `benchlens:l-f23`, port 8080,
7 fixture runs imported):

| Run | Request | Result |
|---|---|---|
| token, `-p 127.0.0.1:8080:8080` | `Host: evil.example:8080`, `/api/health` and `/` | 403 `it is not in allowed_hosts` |
| | `localhost:8080`, `127.0.0.1:8080`, `[::ffff:7f00:1]:8080` | 200 |
| token, `-p 8080:8080` | by the host's LAN IP (172.19.145.89) | 200 |
| | `Host: bench.lan:8080` | 403 |
| token, `-e BENCHLENS_ALLOWED_HOSTS=bench.lan` | `bench.lan:8080`, `localhost` | 200; start-up `Host names served: localhost, IP addresses, bench.lan` |
| | `evil.example` | 403 |
| no token | `DELETE /api/runs/...` | 403 writes turned off |
| | `evil.example` | 403 (as in 0.1.1) |
| token, mounted `benchlens.toml` with `allowed_hosts = ["bench.lan"]` | `bench.lan` | 403, file hidden by the image default (see below) |
| same, `-e BENCHLENS_ALLOWED_HOSTS=` | `bench.lan` 200, `evil.example` 403 | file list used |
| token, `-e BENCHLENS_ALLOWED_HOSTS=`, no file | | `Host names served: any` (documented opt-out) |
| `docker compose -p bl-l up -d --build` (repo file, token from the shell) | `/api/health` from the host | 200; `evil.example` 403 |

- **Published on 0.0.0.0 vs 127.0.0.1**: same behaviour; the port is not checked, so `-p 9000:8080` keeps
  working. Opening by IP from the LAN works.
- **Reverse proxy in front**: a proxy that passes its public name (Caddy default, nginx `Host $host`) gets
  403 until the name is listed; the 403 says what to set. A proxy *container* that reaches benchlens by
  service name (nginx `proxy_pass http://benchlens:8080;` sends `Host: benchlens:8080`, `$proxy_host`) is a
  name too: not mentioned before; added to guide, CHANGELOG and api.md (which claimed nginx's default is
  always an IP).
- **Health checks**: the image has no `HEALTHCHECK`; compose has none. Kubernetes `httpGet` probes send the
  pod IP as `Host`: served.
- **The 403 leaks nothing**: with `bench.lan` configured, a refused `evil.example` gets a detail naming only
  `evil.example`; the token is never printed (unchanged code, `host_refused`).
- **Docker env semantics**: an explicit `-e BENCHLENS_ALLOWED_HOSTS=...` replaces the image `ENV`; nothing
  is lost because `localhost` and IPs are always served. Compose does not interpolate the variable (no
  `${BENCHLENS_ALLOWED_HOSTS:-}` that would blank the default): good, keep it that way.

### Precedence: env default beats a mounted benchlens.toml (fixed: warning)

The documented order is flags > environment > file, and the image default is an `ENV`, so `allowed_hosts`
in a mounted `benchlens.toml` was ignored **without any message**, and the 403 even suggests setting
`allowed_hosts` in benchlens.toml, which then has no effect. Changing the precedence for one key (or adding a
separate "image default" variable) would break the simple rule or add configuration surface for a 0.1.x
patch. Fix kept small: `Settings` records the file's list when the environment hides a different one
(`file_hosts_ignored`), and `Settings::warnings()` (was `warning()`) prints at start-up:

```text
warning: allowed_hosts in the config file (bench.lan) is ignored: BENCHLENS_ALLOWED_HOSTS (localhost) wins over the file (the Docker image sets it to localhost); put the names in BENCHLENS_ALLOWED_HOSTS, or set it to an empty value to use the file's list
```

No warning when the lists are equal after clean-up or when the variable is empty. An empty file list hidden
by the variable is warned about as `(none)`. Unit test `config::tests::env_hiding_file_hosts_warns`;
checked live in the container (output pasted in the guide). Left as follow-ups: F25 (the 403 could name only
the setting that works) and F26 (a lower-priority image default, if users trip over it).

## F24: `config::is_loopback(ip) = ip.to_canonical().is_loopback()`

`IpAddr::to_canonical` is stable since Rust 1.75; `cargo +1.89 check --locked --workspace --all-targets`
passes. The three users of `is_loopback()` on the listen address (`Access::for_listen`, the no-token
warning, the start-up line) all switched; no other `is_loopback` call in the workspace.

| Listen | Check |
|---|---|
| `127.0.0.1`, `127.9.8.7`, `::1`, `::ffff:127.0.0.1`, `::ffff:127.1.2.3` | loopback (unit test) |
| `0.0.0.0`, `::`, `192.168.1.5`, `::ffff:192.168.1.5`, `::ffff:0.0.0.0` | not loopback (unit test) |
| live `[::ffff:127.0.0.1]:18190`, no token | `writes open (loopback, no token)`, `evil.example` 403, `DELETE` reaches the handler (404) |
| live `[::ffff:127.0.0.2]:18191`, token | `evil.example` 403 "on a loopback address", by IP 200 |
| live `[::1]:18192`, token | `evil.example` 403 |

`Host: [::ffff:7f00:1]:8080` is parsed as an IP and served (unit test and in the container). The
deprecated IPv4-compatible form `::127.0.0.1` is not loopback for the kernel either; not mapped, correct.
